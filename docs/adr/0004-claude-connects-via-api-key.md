# Connect Claude through the user's own API key

Rocky connects Claude models only through an Anthropic API key that the user creates in Claude Console, so usage is billed to the key owner's API credits. Max and Team subscribers use the monthly API credits included with their plan through this same path; Pro and Free users pay as they go. Rocky does not offer a Claude.ai login, does not use Claude subscription OAuth tokens, does not mint API keys through a Claude.ai/Console OAuth login, and does not drive the user's installed Claude Code binary.

Anthropic's Claude Code legal page forbids third-party developers from offering Claude.ai login in their own applications, routing requests through Free/Pro/Max credentials, or collecting, storing, or intermediating Claude.ai credentials or session tokens; sign-in must complete through Anthropic's own flow. Anthropic does not publish a way for third parties to register their own OAuth client, so any in-app "Sign in with Claude" today would have to reuse Claude Code's OAuth client, which is the identity misrepresentation the support center prohibits. Tools that do this, such as pi, work because Anthropic currently bills detected third-party traffic to the user's usage credits rather than plan limits, but that is a discretionary tolerance that has changed several times in 2026 and puts the risk on the user's account. Rocky targets non-developer users who cannot judge that risk, so it does not take this path even though billing would land on the user's credits either way.

The connect flow opens the Console API keys page in the user's browser, detects a copied `sk-ant-api` key from the clipboard once when the Rocky window regains focus (with a paste field as fallback), verifies it with `GET /v1/models`, and stores it encrypted with Electron `safeStorage`. Because a regular API key cannot read the remaining credit balance, Rocky shows its own estimate of this month's spend from response usage and links to Console for the balance.

If Anthropic grants Rocky its own OAuth client for key provisioning or lists Rocky as an allowed third-party tool, only the login steps of the connect flow change; the stored credential remains an API key billed to the user.
