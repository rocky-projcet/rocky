## 한 줄 컨셉

**"비서를 고용해서, 내 일을 하나씩 넘겨준다."**

v1이 "AI 직원을 만들고 스킬을 장착하는 관리 콘솔"이었다면, v2는 "로키라는 비서 한 명과 대화하고, 로키가 팀을 꾸려 일을 나눠 맡고, 나는 결정만 하는" 경험이다.

## 원칙

1. **대화가 기본, 화면은 필요할 때만.** 기본 화면은 로키와의 대화 하나. 작업 과정·파일·결정은 오른쪽에서 튀어나오는 패널로 보여 주고, 다 보면 닫힌다.
2. **다음 할 일이 항상 하나 보인다.** 빈 화면을 만들지 않는다. 입력창 위 "다음 한 걸음" 칩, 위쪽 브리핑 줄, 첫 만남의 3단계가 그 역할을 한다.
3. **결정만 사용자에게.** 사용자에게 올라오는 건 "결정 필요"와 "보고" 두 종류뿐이다. 팀원의 질문은 로키가 먼저 걸러내고, 대신 답한 건 숨기지 않고 남긴다.
4. **신뢰는 단계로.** 업무마다 위임 단계(함께 하기 → 초안까지 → 하고 보고 → 맡기기)가 있고, 기록이 쌓여야 다음 단계가 열린다. 올리는 건 로키가 제안하고 사용자가 승인한다.
5. **키우는 감각.** 에이전트는 "로키와 함께" 또는 "직접" 키운다. 개선은 항상 diff와 근거로 보여 주고, 버전으로 되돌릴 수 있다.

## 정보 구조

왼쪽 레일 5개(아이콘 + 짧은 라벨, 아이콘만 두면 헤매기 쉬워서 라벨을 붙인다):

| 레일 | 성격 | 내용 |
| --- | --- | --- |
| 로키 | 페이지 (기본) | 로키와의 대화. 대화 기록은 헤더의 기록 버튼으로 튀어나옴 |
| 결정 | **시트** (페이지 아님) | 어느 화면에서든 오른쪽에서 튀어나옴. 배지에 대기 수 |
| 업무 | 페이지 | 넘긴 업무 목록 + 업무 넘기기 인터뷰 |
| 팀 | 페이지 | 로키(고정) + 에이전트 + 로키의 새 에이전트 제안 |
| 연결 | 페이지 (아래쪽) | 모델 연결(구독/API 키/내 컴퓨터), 모델 역할 |

v1 메뉴(홈·검색·연동·즐겨찾기·작업·공용 스킬·내 에이전트·스킬 템플릿·서비스·보관함 10개)에서 5개로 줄인다. 검색은 나중에 명령 팔레트(Ctrl/Cmd+K)로, 보관함은 각 목록의 필터로 흡수한다.

## 핵심 흐름

### 첫 만남 (시안 1)

"설정 화면"이 아니라 "비서가 출근한 첫날". 세 단계만 보인다.

1. **생각할 모델 연결** — ChatGPT 로그인을 추천으로 고정. API 키, 내 컴퓨터 모델(자동 탐지 결과를 바로 표시)을 옆에 둔다.
2. **나에 대해 알려주기** — 로키가 세 가지를 묻는 대화. 답은 지식 파일(`me.md`)로 저장된다는 걸 알려 준다.
3. **첫 번째 일 넘기기** — 흔한 일 4개 카드 + 직접 말하기. 고르면 업무 넘기기 인터뷰로 이어진다.

### 로키에게 맡기기 (시안 2)

- 사용자가 말하면 로키가 계획을 말하고, 위임은 **대화 안의 접힌 카드**로 보인다(팀원, 요청 한 줄, 상태, 결과 파일).
- 카드를 누르면 오른쪽 패널에 팀원의 실제 작업 과정(도구 호출 타임라인, 로키가 대신 답한 질문, 결과)이 나온다.
- 팀원이 막히면 대화 안에 **결정 카드**가 끼어든다. 로키 추천이 검정 버튼, "다음부터 이 기준으로 기억하기"가 기본 체크.
- 끝나면 토스트로 알린다.

### 결정함 (시안 3)

- 탭: **결정 필요** / **보고** / **로키가 대신 답함**.
- 카드 문법 하나로 질문·권한·제안을 모두 표현: 종류 태그 → 출처(팀원·업무) → 한 문장 질문 → 왜 AI가 못 정하는지 → 선택지(추천이 첫 번째, 검정).
- 작업을 막고 있는 결정에는 "작업이 멈춰 있어요" 태그.

### 업무 넘기기 (시안 4)

- 왼쪽은 로키의 인터뷰, 오른쪽은 실시간으로 채워지는 업무 카드.
- 위쪽 6칸 진행 표시: 무엇을 · 언제 · 결과물 · 잘했다의 기준 · 주의할 점 · 맡길 팀원.
- 맡길 팀원은 로키가 근거(작업 수, 승인율)와 함께 추천.
- 위임 단계 사다리: 처음엔 "초안까지", 위 단계는 잠겨 있고 조건을 보여 준다.
- 마지막 버튼은 "저장"이 아니라 **"지난주 데이터로 한번 해보기"**.

### 팀과 에이전트 키우기 (시안 5, 6)

- 팀 화면 맨 위에 로키(검정 카드, 지식 파일·팀원·업무 수). 그 아래 팀원 카드.
- 팀원 카드에는 판단에 필요한 것만: 역할 한 줄, 모델, 키우기 방식, 맡은 업무와 위임 단계(점 4개).
- 로키의 새 에이전트 제안은 점선 카드로 섞여 들어온다("최근 2주간 일정 조율 요청 9번").
- 에이전트 화면의 "키우기 방식" 토글이 화면 성격을 바꾼다. 로키와 함께면 맨 위에 개선 제안 diff, 직접이면 편집기가 주인공이고 "로키 의견 듣기" 버튼만 남는다.
- 오른쪽 요약 열: 모델(대체 모델 포함), 도구(위험 등급 + 자동/물어보기/끔), 볼 수 있는 지식, 맡은 업무와 다음 단계까지 남은 승인 수.

### 연결 (시안 7)

- 추천 연결(ChatGPT 구독, Claude API 크레딧) / API 키 / 내 컴퓨터 세 묶음, "하나만 있어도 시작할 수 있어요"를 먼저 말한다.
- Claude는 **API 크레딧(사용자 본인 API 키)으로 연결**한다(엔진 설계 §3.5, ADR 0004). "Claude 연결"은 3단계: Console 키 화면 열기 → 복사한 키를 Rocky가 감지 → 확인 후 이 컴퓨터에만 암호화 저장. Max·Team 구독자에게는 매달 포함된 API 크레딧을 안내한다.
- Claude 카드는 남은 크레딧 대신 "이번 달 Rocky에서 쓴 금액(추정)"을 보여 주고, 잔액은 Console 링크로 연다(일반 API 키로는 잔액 조회 불가).
- 로컬 모델은 자동 탐지하고 "도구 지원 / 대화 전용"을 구분한다.
- 모델 역할 4칸(깊게 생각 · 균형 · 빠르게 · 로컬 전용)은 로키가 팀원 모델을 추천하는 기준이다.

## 문구 톤

- 해요체, 짧게. 기존 톤 유지.
- 용어: "에이전트"는 화면에서 **팀원**으로 부르는 것을 허용(팀 화면 제목은 "팀"). "소울"은 **지침**, "스킬"은 쓰지 않는다.
- 한국어 줄바꿈이 단어 중간에서 끊기지 않게 `word-break: keep-all`을 기본으로 한다.
- 결정 문구는 "왜 AI가 못 정하는지"를 한 문장으로 꼭 붙인다.

## 시안 보는 법

`.claude/launch.json`의 `v2-mockups` 설정이 저장소 루트를 정적 서버(포트 4317)로 연다. 그 다음 `http://localhost:4317/docs/v2/mockups/index.html`. 정적 서버 없이 파일을 직접 열어도 되지만 일부 브라우저는 로컬 동영상을 막는다.

시안 안에서:

- 위쪽 검정 바에서 화면 7개를 오간다. 주소 해시(`#home`, `#agent` 등)로 바로 열 수도 있다.
- "설계 메모"로 화면별 설계 의도를 켜고 끈다.
- 눌러 볼 수 있는 것: 위임 카드(오른쪽 패널), 결정 카드 선택지(결정 반영·배지 감소), 레일의 결정(시트), 결정함 탭, 첫 만남 단계, 위임 단계 사다리, 키우기 방식 토글. 홈에 들어가면 2초 뒤 완료 토스트가 뜬다.

## 열린 질문

1. 로키 대화는 "하나의 긴 대화"인가, "주제별 대화 여러 개"인가. 시안은 주제별(헤더에 제목 + 기록 버튼)로 그렸다. 비서 느낌만 보면 하나의 긴 대화가 더 자연스럽지만, 컨텍스트 관리는 주제별이 유리하다.
2. 업무 화면(레일 "업무")의 목록 화면은 아직 그리지 않았다. 팀 카드의 업무 표시와 겹치므로, 목록을 따로 둘지 팀 화면에 합칠지 정해야 한다.
3. 다크 모드: v1도 사실상 라이트 전용이었다. v2도 라이트로 시작할지.
